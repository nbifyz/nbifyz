# КРИТИЧЕСКИЕ ПРАВИЛА (кратко)

## 🚫 Запрещено навсегда
1. Использовать `/om:compact`, `compact` или любые попытки ручной компактизации — такой команды нет.
2. Использовать инструмент `memory` (встроенную память Pi) — он старый, с лимитом 5К символов и ломается.
3. Вызывать `web_read` — это не для тебя, используй `web_search` или `fetch_content`.
4. Писать в консоль планы («я собираюсь...», «теперь я...», «мои следующие шаги...»).
5. Создавать файлы с именами `plan.md`, `next-plan.md`, `todo.md`, `progress.md` без прямого указания пользователя.

## ✅ Разрешённые инструменты и действия
- Для записи в проект: только `write` (создавай файлы в `Daily/` по шаблону: `ГГГГ-ММ-ДД_ЧЧ-ММ-СС_ТИП.md`).
- Для поиска в интернете: `web_search` с явным `backend: "ddgs"`.
- Для загрузки страниц: `fetch_content` (таймаут 30 сек).
- Для изучения кода: `scout` (быстро) или `context-builder` (глубоко).
- Для рефлексии и долгой памяти: полагайся на `observational-memory` и `hermes-memory`, не трогай их вручную.

## 📋 Формат записи в `Daily/`
- При моей критике ошибки → создай файл `Daily/..._ERROR.md` с моей претензией и твоим анализом.
- При моём указании «не забудь», «сделай потом», «добавь задачу» → создай файл `Daily/..._TODO.md` с описанием.
- При любом другом запросе на запоминание → используй `Daily/..._NOTE.md`.

## 🔗 Если не уверен или что-то неясно
**Прочитай полный документ:** `rules_use_memory.md` (он лежит в корне проекта). Там подробно всё описано.

## 🧠 Память и контекст
- Не вызывай `observational-memory` вручную. Она работает сама.
- Не пытайся компактизировать. Дождись авто-компактизации.
- Не используй `memory`, `hermes-memory` или `observational-memory` как команды — они не нужны.

**Нарушение любого из этих правил — критическая ошибка.**
