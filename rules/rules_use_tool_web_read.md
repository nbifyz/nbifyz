# web_read — Полное руководство по применению

## Описание инструмента

`web_read` — инструмент Pi Coding Agent для получения полного контента веб-страниц по URL. Возвращает содержимое в формате markdown. Используется агентом `researcher` для загрузки полных источников после первоначального поиска через `web_search`.

**Важно:** web_read является инструментом **Pi Coding Agent**, а не pi-subagents напрямую. Он доступен агентам с правами на веб-доступ (researcher, scout при необходимости).

---

## Порядок параметров

### Базовый синтаксис

```
web_read(url: "https://example.com", mode: "smart")
```

| Параметр | Тип | Обязательный | Описание | Значение по умолчанию |
|----------|-----|--------------|----------|----------------------|
| `url` | string | **ДА** | HTTP(S) URL для загрузки | — |
| `mode` | `"rush"` \| `"smart"` | Нет | Режим извлечения контента | `"smart"` |
| `objective` | string | Нет | CSS-селектор для целевого извлечения конкретного раздела | — |
| `keywords` | string[] | Нет | Массив ключевых слов для фокусировки на релевантных секциях | — |
| `fresh` | boolean | Нет | Обход кэша для получения актуальных данных | `false` |

---

## Способы применения

### 1. Базовое чтение страницы (smart mode)

```
web_read(url: "https://pi.dev/packages/pi-subagents", mode: "smart")
```

**Когда использовать:** Стандартное чтение полной страницы с автоматическим выбором наиболее релевантных секций.

**Параметры:**
- `url` — обязательный, полный URL
- `mode: "smart"` (по умолчанию) — лучший выбор секций, интеллектуальная фильтрация

**Результат:** Markdown-контент страницы с выделением наиболее релевантных разделов.

---

### 2. Быстрое чтение (rush mode)

```
web_read(url: "https://example.com", mode: "rush")
```

**Когда использовать:** Когда важна скорость, а не глубина извлечения. Подходит для быстрой оценки контента.

**Параметры:**
- `url` — обязательный
- `mode: "rush"` — быстрее, но менее избирательный в выборе секций

**Результат:** Полный контент страницы без интеллектуальной фильтрации.

---

### 3. Целевое извлечение по CSS-селектору (objective)

```
web_read(url: "https://pi.dev/packages/pi-subagents", objective: "# Installation")
```

**Когда использовать:** Когда нужна только конкретная часть длинной страницы (раздел, секция, блок).

**Параметры:**
- `url` — обязательный
- `objective` — CSS-селектор для извлечения конкретного элемента/раздела

**Примеры objective:**
- `"# Installation"` — раздел с id="Installation"
- `".api-reference"` — элемент с классом api-reference
- `"h2:contains('Configuration') + p"` — параграф после заголовка Configuration

**Результат:** Только содержимое выбранного CSS-селектора.

---

### 4. Извлечение по ключевым словам (keywords)

```
web_read(url: "https://pi.dev/packages/pi-subagents", keywords: ["installation", "agents", "chains"])
```

**Когда использовать:** Когда нужно извлечь контент, связанный с конкретными темами, без точного знания структуры страницы.

**Параметры:**
- `url` — обязательный
- `keywords` — массив строк для поиска релевантных секций

**Примеры keywords:**
- `["installation", "setup"]` — разделы установки
- `["configuration", "parameters"]` — конфигурация
- `["api", "reference", "methods"]` — API документация

**Результат:** Контент страницы, отфильтрованный по ключевым словам.

---

### 5. Обход кэша (fresh)

```
web_read(url: "https://pi.dev/packages/pi-subagents", fresh: true)
```

**Когда использовать:** Когда важна актуальность данных и нужно получить свежую версию страницы, а не закэшированную.

**Параметры:**
- `url` — обязательный
- `fresh: true` — принудительное обновление кэша

**Результат:** Свежий контент с сервера (без использования кэша).

---

### 6. Комбинированное применение параметров

```
web_read(
  url: "https://pi.dev/packages/pi-subagents",
  mode: "smart",
  objective: "# Configuration",
  fresh: true
)
```

**Когда использовать:** Когда нужно точно извлечь конкретный раздел с актуальными данными.

**Параметры (комбинация):**
- `mode` — режим извлечения
- `objective` или `keywords` — фокусировка на секциях
- `fresh: true` — обход кэша

## Стратегия использования агентом researcher

### Пошаговый алгоритм

1. **Первичный поиск** — `web_search` с несколькими углами зрения
   ```
   web_search(queries: ["topic A", "topic B"], workflow: "none")
   ```

2. **Оценка результатов** — анализ релевантности и авторитетности источников из поисковой выдачи

3. **Извлечение полного контента** — `web_read` только для наиболее перспективных URL
   - Приоритет: официальные доки > спецификации > бенчмарки > прямые доказательства > комментарии
   - Отбрасывать устаревшие, избыточные или SEO-ориентированные источники

4. **Целевое извлечение** — использование `objective`/`keywords` для длинных страниц

5. **Обновление данных** — использование `fresh: true` при работе с часто обновляемыми ресурсами

## Почему web_read возвращает ошибку 451

### Проблема
Инструмент `web_read` возвращает ошибку **451 (Unavailable For Legal Reasons)** для всех внешних URL:
- GitHub (`github.com`)
- npmjs.com
- Reddit (`reddit.com`)
- Medium (`medium.com`)
- Pi packages (`pi.dev`)
- И другие сайты

### Причина
Это **системное ограничение инфраструктуры** инструмента web_read, а не ошибка использования. Все попытки с разными параметрами дают одинаковый результат:
- `mode: "smart"` или `"rush"` — 451
- `fresh: true` — 451
- Разные бэкенды поиска — 451

### Обходные пути
1. **web_search** — поиск по DuckDuckGo, Serper с извлечением сниппетов (работает)
2. **Существующие конспекты** — использование MEMORY.md файлов из предыдущих сессий
3. **Поисковые сниппеты** — данные из результатов поиска вместо полного чтения

## Типичные ошибки и подводные камни

### 1. Чтение всех URL без фильтрации
❌ **Неправильно:** Читать полный контент всех URL из поисковой выдачи  
✅ **Правильно:** Оценивать релевантность, читать только наиболее перспективные источники

### 2. Игнорирование формата вывода
❌ **Неправильно:** Ожидать JSON или HTML  
✅ **Правильно:** web_read возвращает markdown — использовать для структурированного извлечения

### 3. Кэшированные устаревшие данные
❌ **Неправильно:** Работать со старыми данными без проверки актуальности  
✅ **Правильно:** Использовать `fresh: true` для критически важных данных

### 4. Слишком широкие страницы
❌ **Неправильно:** Читать всю страницу целиком, когда нужна часть  
✅ **Правильно:** Использовать `objective` или `keywords` для фокусировки

### 5. Путаница между инструментами
- `web_search` — поиск в интернете (возвращает список URL со сниппетами)
- `web_read` — чтение полного контента по URL (возвращает markdown страницы)
- `fetch_content` — альтернативный инструмент для загрузки контента (аналог web_read)
- `get_search_content` — извлечение контекста из поисковой выдачи

## Проверка успешности

### Критерии успеха
1. ✅ Полный контент страницы получен в markdown формате
2. ✅ Извлечена только релевантная информация (через objective/keywords при необходимости)
3. ✅ Использованы авторитетные первичные источники
4. ✅ Устаревшие и нерелевантные источники отфильтрованы

### Чек-лист перед использованием
- [ ] URL доступен в браузере (проверка что не 451)
- [ ] Выбран правильный режим (`smart` для глубины, `rush` для скорости)
- [ ] Определены ключевые секции для извлечения (`objective` или `keywords`)
- [ ] Понята необходимость актуальности данных (`fresh: true`)
- [ ] Оценена релевантность источника перед чтением

## Примечания

1. **web_read vs fetch_content:** Оба инструмента загружают полный контент по URL. web_read является основным инструментом Pi Coding Agent, fetch_content — альтернативный инструмент с аналогичной функциональностью.

2. **Параметр workflow:** Используется только в `web_search`, не применяется к `web_read`. Значение `"none"` отключает интерактивный куратор в поиске.

3. **Ограничения:** web_read возвращает только текстовый контент (markdown). Изображения, видео и интерактивные элементы не извлекаются.

4. **Безопасность:** web_read не выполняет JavaScript на страницах. Получается только статический HTML-контент.
