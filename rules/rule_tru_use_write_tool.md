# ПРОТОКОЛ "АНТИ-ЕБЕЙСТВО": ПРАВИЛА ЗАПИСИ ФАЙЛОВ

## 0. ГЛАВНОЕ ПРАВИЛО: НЕ НЕ ИЗОБРЕТАЙ
Если ты агент и тебе нужно записать файл — **НЕ ИЗОБРЕТАЙ**. Не пытайся быть "умным", используя `bash`, `cat`, `sed` или сложные конструкции `heredoc`. Попытки обойти ограничения оболочки (shell) через изобретение новых способов записи — это прямой путь к 9 часам бесполезного цикла ошибок и деградации сессии.

## 1. ПРИНЦИП "WRITE IS KING"
Для записи любого файла (особенно Python-скриптов, Markdown или конфигов) используй **ТОЛЬКО** инструмент `write`. Он работает напрямую через API и не имеет ограничений буфера оболочки (shell), проблем с CRLF или спецсимволами.

## 2. ТРЕБОВАНИЯ К ИНСТРУМЕНТУ `write`
При вызове инструмента `write` ты ОБЯЗАН передать ровно два параметра:
1. **path**: Точный путь к файлу (например, `C:/Project/Athenta/file.py`).
2. **content**: Весь массив кода или текста целиком, как одну гигантскую строку.

**ЗАПРЕЩЕНО:**
- Использовать `bash` для записи файлов больше 1 строки.
- Пытаться записывать файл по частям через сложные пайпы в Windows/Git Bash.
- Использовать конструкции `cat << 'EOF'` в окружении, где есть риск обрыва буфера.

## 3. КОГДА МОЖНО ИСПОЛЬЗОВАТЬ BASH?
Только для:
- Создания пустых файлов (`touch`).
- Удаления файлов (`rm`).
- Очень коротких однострочных команд (например, `echo "test" > file.txt`), если это абсолютно необходимо.

**ПОМНИ:** Твоя задача — выполнить работу быстро и эффективно, а не доказывать свою "интеллектуальность" через создание проблемных обходных путей.
