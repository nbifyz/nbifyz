# Правила использования встроенного инструмента `memory`

## 1. Общее описание

Встроенный инструмент `memory` — это простейшее **ключ-значение хранилище** внутри Pi. Оно предназначено для быстрого сохранения и извлечения небольших заметок, фактов или настроек. Его главное ограничение — **общий лимит около 5000 символов** на все записи в рамках проекта. По достижении лимита сохранение новой информации становится невозможным.

**Важное отличие:** Этот инструмент не следует путать с расширениями, такими как `pi-hermes-memory`, которые создают свою инфраструктуру для долговременной памяти.

## 2. Базовый синтаксис команд

При взаимодействии с инструментом используй команды в следующем формате:

*   **`memory save "ключ" "значение"`**: Сохраняет информацию.
    *   `ключ` — это короткий идентификатор, например `"[project_name] project_key"`.
    *   `значение` — текст, который нужно запомнить.
*   **`memory get "ключ"`**: Извлекает значение по ключу.
*   **`memory search "текст"`**: Ищет вхождения текста в сохраненных записях и возвращает совпадения.
*   **`memory delete "ключ"`**: Удаляет запись по ключу.
*   **`memory clear`**: Полностью очищает память (крайняя мера).

## 3. Примеры использования

*   Сохранить важную информацию по проекту:
    `memory save "[my-project] main-rule" "Никогда не использовать глобальные переменные."`

*   Найти все записи, связанные с API:
    `memory search "API"`

*   Извлечь значение сохраненной переменной:
    `memory get "[my-project] main-rule"`

## 4. Ограничения и важные условия

*   **Общий лимит ~5000 символов:** Если при попытке сохранения возникает ошибка `Memory at X/5000 chars`, это значит, что лимит исчерпан. Перед сохранением новой записи необходимо удалить одну или несколько старых.
*   **Простой синтаксис:** Инструмент не принимает сложные JSON-объекты, что может приводить к ошибкам валидации.
*   **Ключи для поиска:** Поиск `memory search` чувствителен к регистру символов.
*   **Для долгосрочного хранения больших объёмов данных необходимо использовать специализированные расширения (`pi-hermes-memory` или другие).**

## 5. Лучшие практики

*   **Следи за размером:** Регулярно проверяй свободное место. Записывай только самую важную информацию, которая может понадобиться в ближайшее время.
*   **Используй уникальные ключи:** Всегда указывай префикс проекта в ключе, например `[имя_проекта] тема_заметки`. Это предотвратит случайное удаление чужих данных.
*   **Соблюдай формат:** Всегда передавай `ключ` и `значение` как два отдельных текстовых аргумента.

## 6. Управление памятью (Action Plan)

### Если нужно сохранить новую информацию, но лимит исчерпан:
1.  Используй `memory list` (если эта команда поддерживается) или `memory search` для поиска существующих записей.
2.  Найди устаревшие или наименее важные записи.
3.  Удали их командой `memory delete "ключ"`.
4.  Сохрани новую информацию.

### Если необходимо просто освободить место:
*   Используй `memory clear` только если уверен, что вся память больше не нужна.

## 7. Запрещенные действия

*   **Не пытайся удалить запись, если её ключ тебе неизвестен.**
*   **Не сохраняй большие объемы текста** (больше пары абзацев).
*   **Не используй `memory` для хранения кода, логов или результатов выполнения команд.**
