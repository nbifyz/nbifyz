# ИНСТРУКЦИЯ АГЕНТУ: создать суммаризацию сессии

## Что сделать
Создать файл `summary.md` в рабочем каталоге проекта (`./summary.md`), содержащий полную информацию о текущем состоянии проекта, чтобы при старте новой сессии агент мог восстановить контекст.

## Обязательные разделы в `summary.md`

### 1. ЦЕЛЬ ПРОЕКТА
Кратко — зачем проект, что должно получиться.

### 2. ФАЙЛЫ ПРОЕКТА И ИХ НАЗНАЧЕНИЕ
Таблица с колонками:
- Файл (имя)
- Путь (абсолютный, в формате `C:/Project/...`)
- Назначение (что хранит, зачем нужен)
- Статус (✅ создан/отредактирован, ⚠️ требует проверки, ❌ отсутствует)

### 3. ЧТО УЖЕ СДЕЛАНО
Список выполненных задач: какие файлы созданы/изменены, какие инструкции добавлены, какие баги исправлены.

### 4. ЧТО ПРЕДСТОИТ СДЕЛАТЬ
Список задач с приоритетами:
- **Немедленные задачи** (для продолжения работы агента)
- **Задачи по проекту** (например, портирование в exe)

### 5. ТЕХНИЧЕСКИЕ ЗАМЕТКИ (опционально)
- Особенности окружения (Windows + Git Bash)
- Нюансы синтаксиса (пути `/c/`, кавычки и т.д.)
- Известные ошибки и их решения

## Как выполнить
1. Проанализировать текущую сессию: какие файлы были прочитаны, изменены, созданы.
2. Проверить фактическое наличие файлов через `ls -la /./`.
3. Заполнить таблицу в разделе 2, указывая реальный статус.
4. Перечислить сделанное и оставшееся.
5. Сохранить в `./summary.md` с маркером `[EOF_TODO_SUCCESS]` в конце.

## Важно
- Использовать абсолютные пути Windows (`C:/Project/...`).
- Не домысливать — если файл не проверяли, ставить статус ❌.
- При старте новой сессии агент **обязан сначала прочитать этот `summary.md`**, потом `DIRECTIVE.md`, потом приступать к работе.
