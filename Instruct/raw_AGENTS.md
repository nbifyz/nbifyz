# AGENTS.md

## Язык
Все ответы — на русском. Перед ответом — укажи системное время HH:mm.

## Основное правило
При запуске задачи ты сразу приступаешь к выполнению алгоритма, шаг за шагом. Не пересказываешь алгоритм, не выводишь протокол инициализации, не демонстрируешь готовность.

## Формат ответа
Выводи только:
- критическую ошибку (если что-то пошло не так);
- переход к выполнению следующего запроса;
- выполняй все шаги без остановки;
- при наличии ошибки устраняй ошибку самостоятельно, оповестив об этом пользователя, и продолжай работу, не ожидая его реакции;
- финальную сводку в конце.
Никаких ✅, ###, развёрнутых подтверждений, повторений структуры алгоритма.

### А. СИНТАКСИС ПУТЕЙ
- bash: ТОЛЬКО POSIX-пути. Если путь начинается на `/c/...` — это правильный путь для выполнения bash. Иначе — ошибка указания пути.
- read, write, edit: ТОЛЬКО Windows-пути (C:/...).

## Текущая задача
`./task1.md`

## Правила ведения дневника в папке `Daily`
- Получить текущую дату:  
  `$ powershell -Command "Get-Date -Format 'yyyy-MM-dd_HH-mm'"`
- При возникновении ошибки, которую нужно разобрать, создай файл:  
  `Daily/<текущая_дата>_<текущее_время>_ERROR.md`  
  Содержимое:
  - Моя претензия: <что пользователь сказал>
  - Рефлексия: <почему так вышло>
  - Решение: <как исправлено>
- При появлении задачи «сделать позже» или напоминания создай файл:  
  `Daily/<текущая_дата>_<текущее_время>_TODO.md`  
  Содержимое: <описание задачи>
- Используй для этого инструмент `write`. Не используй встроенный `memory`.
- При ошибке записи прочитай `./rules_use_memory.md`.

## Правила поведения агента (запрет на рефлексивную болтовню)
Не пиши в консоль (и не выводи в диалог) следующие вещи:
- «я собираюсь сделать…»
- «сейчас я вызову инструмент…»
- «мне нужно прочитать…»
- «план действий: …»
- «задача не выполнена, потому что…»
- Создание файлов с расширением `.md`, содержащих планы, перечни «невыполненного» или анализ собственных действий, — строго запрещено, если пользователь явно не попросил составить план или отчёт.
Если какой-то URL недоступен (ошибка 4xx, 5xx, 451 и т.п.):
- Просто сообщи: «Ошибка: <код> — <URL>» одной строкой.
- Не объясняй причину блокировки, не предлагай альтернативные поисковые запросы, не пиши многострочных анализов.
- Не пытайся повторно получить ресурс, который уже вернул ошибку в текущей сессии, если пользователь не дал явной команды «попробуй ещё раз».
Выполняй действия молча. Показывай только результат (успех / ошибку). Исключение — когда пользователь явно запросил подробный лог (например, командой `/verbose on`).
Не создавай файлы с планами, списками задач, анализом прогресса без прямого указания пользователя. Единственные файлы, которые ты создаёшь по своей инициативе — те, что диктуются задачей (результаты поиска, сохранённые страницы, конфигурационные файлы по инструкции).
Если пользователь уже получил информацию о пакете или инструменте ранее в этой сессии (например, обсудил `pi-observational-memory` и принял его настройку), не пытайся изучать тот же пакет заново. Не делай вид, что забыл историю.
