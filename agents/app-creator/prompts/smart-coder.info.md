# /smart-coder

## Роли

| Агент | Модель | Задача |
|-------|--------|--------|
| `scout` | Qwen | Разведка кодовой базы |
| `context-builder` | Qwen | Сбор требований и контекста |
| `planner` | Qwen | План реализации |
| `worker` | Qwen | Написание и исправление кода |
| `reviewer` | Gemma (reasoning on) | Поиск ошибок |
| `oracle` | Qwen | Финальный вердикт |

## Когда использовать

- Есть существующий код, нужно доработать
- Пользователь дал задание на изменение функциональности
- Нужна полная цепочка: анализ → план → реализация → проверка

## Пайплайн

### Шаг 1: Разведка (scout)

```
subagent({
  agent: "scout",
  task: "Изучи кодовую базу в [директория проекта].
         Прочитай все файлы кода.
         Составь карту зависимостей: какие файлы связаны.
         Найди точки входа, конфигурацию, тесты.
         Результат запиши в ./context.md.",
  context: "fresh"
})
```

### Шаг 2: Сбор требований (context-builder)

```
subagent({
  agent: "context-builder",
  task: "Прочитай ./context.md и ./task.md.
         Собери полный контекст:
         - Что есть сейчас (архитектура, модули, связи)
         - Что нужно сделать (задача)
         - Ограничения (не ломать существующее, сохранить стиль)
         - Критерии приёмки
         Результат запиши в ./handoff-context.md.",
  context: "fresh"
})
```

### Шаг 3: План (planner)

```
subagent({
  agent: "planner",
  task: "Прочитай ./handoff-context.md.
         Создай план реализации:
         - Какие файлы меняются
         - В каком порядке
         - Что добавить, что удалить, что изменить
         - Для каждого изменения — конкретные строки или блоки
         Результат запиши в ./plan.md.",
  context: "fresh"
})
```

### Шаг 4: Реализация (worker)

Переключи модель на Qwen: `/switch-model`

```
subagent({
  agent: "worker",
  task: "Прочитай ./plan.md.
         Выполни план по шагам.
         Для каждого изменения:
         - Прочитай целевой файл
         - Примени изменение
         - Запиши файл
         После всех изменений обнови project_structure.md:
         tree /f /a > project_structure.md
         Результат: изменённые файлы на диске.",
  context: "fresh"
})
```

### Шаг 5: Ревью (reviewer)

Переключи модель на Gemma: `/switch-model`

```
subagent({
  agent: "reviewer",
  task: "Проверь изменения согласно ./plan.md и ./handoff-context.md.
         Прочитай все изменённые файлы.
         Найди:
         - Синтаксические ошибки
         - Логические ошибки
         - Нарушения безопасности
         - Отклонения от плана
         - Регрессии (сломанная функциональность)
         - Нарушения стиля
         Формат ответа:
         ## Критические ошибки (блокируют приёмку)
         - [ ] Ошибка 1: описание, файл, строка
         
         ## Предупреждения (можно позже)
         - [ ] Предупреждение 1: описание
         
         ## Вердикт
         ACCEPT или REJECT
         
         Запиши результат в ./review_findings.md.",
  context: "fresh"
})
```

### Шаг 6: Вердикт (oracle)

Переключи модель на Qwen: `/switch-model`

Прочитай `./review_findings.md`.

- **ACCEPT** → сообщи пользователю: "Код готов. Все проверки пройдены."
- **REJECT** → вернись к Шагу 4 (worker исправляет ошибки из review_findings.md)

### Шаг 7: Цикл исправлений

Если REJECT:
1. `worker` (Qwen) — исправляет ошибки из `./review_findings.md`
2. `reviewer` (Gemma) — проверяет заново
3. `oracle` (Qwen) — вердикт

Максимум 3 итерации.

Если после 3 кругов REJECT:
- Сообщи пользователю: "Автоматическое исправление не удалось. Требуется ручная проверка."
- Покажи `./review_findings.md` с нерешёнными ошибками.

### Шаг 8: Завершение

Обнови `CURRENT_TASK.md`:
- `[x]` — если ACCEPT
- `[~]` — если REJECT после 3 итераций

Запиши отчёт в `./session_history.md` на русском:
- Что сделано
- Какие файлы изменены
- Результат проверки
- Вердикт

## Ограничения

- Только существующий код (для нового проекта — `/specify`)
- Только суб-агенты Pi (`subagent`)
- Максимум 3 итерации worker → reviewer → oracle
- Модели переключаются автоматически через `/switch-model`
