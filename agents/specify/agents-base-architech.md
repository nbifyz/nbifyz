 Архитектура и Компоненты

Система состоит из трех основных типов сущностей, логика которых полностью извлекается из существующей кодовой базы:
2.1. Агенты (Agents)

    Роль: Определяют "Кто делает" (роль, ответственность, контекст).

    Источник логики: Файлы в ./.pi/prompts/speckit.*.md. Каждый файл содержит полный промпт агента с ролью, инструкциями, правилами и форматом вывода. Необходимо тщательно просканировать каждый файл, извлечь: роль агента, его обязанности, правила работы, формат вывода, механизмы передачи (handoff).

    Хранение: После адаптации агенты сохраняются как файлы .md в целевой директории (например, ./agents/<имя_агента>.md).

    Контрактность:

        Вход: Определяется в исходном промпте (чтение конкретных файлов, получение данных от оркестратора). Необходимо адаптировать пути к файлам под целевую среду.

        Выход: Определяется в исходном промпте (запись в конкретный файл, передача через intercom). Формат вывода (Markdown, структура) должен быть сохранён.

    Процесс адаптации: Взять исходный промпт из .pi/prompts/speckit.*.md, преобразовать его в формат целевого агента (с YAML-заголовком), скорректировать пути к входным/выходным файлам, сохранить как отдельный файл агента.

2.2. Скиллы (Skills)

    Роль: Определяют "Как делать" (стандартизированные процедуры).

    Источник логики: Скрипты в .specify/scripts/powershell/ и шаблоны в .specify/templates/. Логика процедур (создание фичи, настройка плана, обновление контекста) извлекается из скриптов .ps1. Структура выходных документов — из шаблонов *-template.md.

    Хранение: После адаптации скиллы сохраняются как SKILL.md в целевой директории (например, ./skills/<имя_скилла>/SKILL.md).

    Структура SKILL.md (Обязательные секции):

        When to Use: Извлечь из комментариев или описания скрипта — в каких случаях он запускается.

        Procedure Steps: Адаптировать пошаговый алгоритм из скрипта .ps1 в текстовые инструкции.

        Pitfalls: Извлечь из проверок ошибок в скриптах (check-prerequisites.ps1, common.ps1).

        Verification Steps: Извлечь из валидаций и проверок, встроенных в скрипты.

    Процесс адаптации: Изучить скрипт, понять его алгоритм, преобразовать код в читаемые текстовые шаги, оформить в SKILL.md.

2.3. Оркестратор (Orchestrator Agent)

    Роль: Управление пайплайном, последовательный/параллельный вызов агентов.

    Источник логики: Файлы .specify/integrations/speckit.manifest.json и .specify/integration.json. Они содержат конфигурацию пайплайна: порядок агентов, их зависимости, правила передачи контекста.

    Функционал:

        Чтение конфигурации пайплайна из speckit.manifest.json.

        Вызов агентов строго последовательно (Chain) или параллельно (Parallel) через subagent.

        Передача результатов через {previous}.

        Сохранение артефактов в ./Prj/.

    Процесс адаптации: Извлечь порядок агентов из манифеста, создать JSON-конфигурацию для оркестратора в целевом формате.

3. Механизмы Управления Контекстом (Наследуемость)

    Источник логики: Поле defaultContext в промптах агентов (если указано) и скрипт update-agent-context.ps1 (определяет, как обновляется контекст между агентами).

    Режимы Контекста:

        fresh: Извлекается из промптов агентов, которые требуют чистого контекста.

        fork: Извлекается из скрипта update-context.ps1 — логика копирования и изоляции контекста родителя.

    Процесс адаптации: Проанализировать, как исходная система управляет контекстом, и воспроизвести эту логику в целевых агентах через поле defaultContext.

4. Алгоритм Работы (Адаптация, а не создание)

    Сканирование кодовой базы: Тщательно прочитать все файлы в .pi/prompts/, .specify/scripts/, .specify/templates/, .specify/integrations/.

    Извлечение логики агентов: Для каждого speckit.*.md — извлечь роль, инструкции, вход/выход, правила handoff.

    Извлечение логики скиллов: Для каждого скрипта .ps1 и шаблона *-template.md — извлечь процедуры, проверки, структуру вывода.

    Извлечение логики оркестрации: Из speckit.manifest.json — порядок агентов и правила передачи данных.

    Адаптация и запись: Преобразовать извлечённую логику в целевые файлы агентов (.md с YAML-заголовком) и скиллов (SKILL.md).

    Проверка: Агент-аналитик сравнивает логику исходных и адаптированных агентов на соответствие.

5. Ограничения и Правила

    Источник истины: Исходная кодовая база (.pi, .specify). Никакая логика не придумывается — только извлекается и адаптируется.

    Адаптация путей: Все пути к файлам в промптах должны быть скорректированы под целевую среду (./Prj/ вместо исходных).

    Сохранение форматов: Markdown-структура вывода агентов и скиллов должна быть сохранена.

    Запрет на фреймворки: LangChain, CrewAI не используются.

6. Критерии Приёмки

    Полнота извлечения: Логика каждого исходного агента и скрипта отражена в адаптированных файлах.

    Идентичность логики: Адаптированный агент выполняет ту же функцию, что и исходный (проверяется агентами-аналитиками).

    Корректность оркестрации: Цепочка агентов выполняется в правильном порядке, данные передаются корректно.

    Структурная целостность: Все адаптированные файлы сохранены в правильных директориях.

    Работоспособность скиллов: Логика скриптов корректно преобразована в читаемые инструкции, которые агент может выполнить.
