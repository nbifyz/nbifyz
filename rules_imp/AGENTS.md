## 🔧 Tool Call Format (STRICT)
- **Формат**: Ответ должен содержать ТОЛЬКО JSON: `{"action": "tool_name", "args": {"param1": "value"}}`.
- **Запреты**: Никакого текста до или после JSON. Не использовать Markdown-блоки (```json```).
- **Пути Windows**: Следуй правилу `rules_imp/00_core/path.md`:
  - **В терминале (bash)**: Прямые слеши `/` + двойные кавычки → `"C:/CLI/Pi/rules_imp"`
  - **В JSON-конфиг**: Двойные слеши `\\` → `"path": "C:\\CLI\\Pi\\rules_imp"`
  - **В тексте (Markdown)**: Одинарные слеши `\` → `%RULES%\00_core\id.md`

- **Чтение фалов и катаоргов толкьвкавычках: `$ ls -la "C:\CLI\Pi\rules_imp"`

## 🛑 STOP & Write Triggers
- **Ключевые слова**: "ЗАПОМНИ", "запиши", "важно", "не забудь".
  → **Действие**: СТОП, записать указанную мысль в `%AD%\persistent_history.log` и подтвердить.
- **Ошибка**: Записать детали в `error_list.md`, затем следовать протоколу `%RULES%10_proc\p_fix.md`.

## 🧠 Контроль Автопилота

**Проблема**: Использование путей из памяти вместо проверки текущего cwd.

**Правила CWD-FIRST** (`%RULES%00_core\autopilot.md`):
1. Перед файловой операцией — проверить текущую директорию
2. Относительные пути (`@`, `./`) — искать ТУТ, не в %AD%
3. Путь из памяти (>5 мин) — верифицировать через find/ls
4. Триггеры STOP: пути из других проектов, `@` без проверки

**Критические операции** (автопилот ЗАПРЕЩЁН):
- Редактирование `%AD%\AGENTS.md`, `.env`
- Удаление/перезапись файлов
- Создание в %AD% вне текущего проекта

**См. полное описание**: `%RULES%\00_core\autopilot.md`

## ♻️ Iteration & Quality Control
При каждой итерации разработки:
1. **Следовать циклу**: `%RULES%10_proc\p_loop.md`.
2. **Использовать навыки**: Применять соответствующие навыки из `%RULES%20_skill`.
3. **Запускать инструменты**: Для проверок использовать инструменты из `%RULES%30_tool`, как указано в `p_loop.md`.
4. **Отчет**: 
   ✅ Задача выполнена → "Проверено по правилам валидации, нарушений нет"
   ❌ Проблема (выполнено частично )→ описать что + что делаю
   🗣 Диалог без действий → ничего не писать  

5. **Рефлексия и Обучение (После задачи)**: После успешного решения нетривиальной задачи, создать новый `.md` файл-урок в директории `/lessons/` с описанием полученного опыта.
