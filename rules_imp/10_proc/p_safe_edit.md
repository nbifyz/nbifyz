# Протокол Безопасного Редактирования и Удаления (p_safe_edit.md)

Этот протокол **обязателен** для выполнения перед **любой** файловой операцией, изменяющей данные, удаляющей их или меняющей атрибуты (например, `replace`, `write_file` (для существующего файла), `Remove-Item`, `Set-ItemProperty`).

Операции чтения (`read_file`, `rg`) не требуют выполнения этого протокола.

---

## 🔒 Принцип I: Truthfulness (Анти-Галлюцинации)

**ПЕРЕД любым редактированием:**

1. **Проверка информации в файлах проекта:**
   - Если задача требует информации о коде/данных — выполнить `rg` поиск или `read_file`
   - **Нет в файле = нет факта.** ЗАПРЕЩЕНО выдумывать информацию
   - Если информация не найдена — сообщить: "Информация не найдена в файлах проекта. Требуется уточнение."

2. **Proof of Search (доказательство поиска):**
   - Каждая ссылка на код/данные должна содержать:
     - Команду поиска: `rg -nH "термин" путь`
     - Имя файла и номер строки
     - Прямую цитату из найденной строки
     - Вердикт: "Данные взяты из исходника на диске"

3. **Проверка зависимостей:**
   - Перед импортом модуля/библиотеки — убедиться, что они установлены
   - Проверить: `package.json`, `requirements.txt`, `Cargo.toml`, `pom.xml` и т.д.

---

## 📝 Полный Процесс (4 шага)

### 0. Проверка Существования Файла
- **Условие:** Всегда, перед любой операцией с файлом (чтение, редактирование, удаление, изменение атрибутов).
- **Действие:** Убедиться, что файл существует по указанному пути.
- **Действие при отсутствии:** Если файл не существует, **прекратить операцию**, сообщить пользователю: "ОШИБКА: Файл '[путь_к_файлу]' не найден. Операция отменена." и занести в `error_list.md`.

### 0.1. Проверка Применимости Файла к Задаче
- **Условие:** После подтверждения существования файла, но перед любым действием.
- **Действие:** Прочитать содержимое файла (или его часть) и сделать вывод о его применимости к текущей задаче. Сообщить пользователю о содержимом и своем выводе.
- **Действие при неприменимости:** Если файл не относится к задаче, **прекратить операцию**, сообщить пользователю: "ОШИБКА: Файл '[путь_к_файлу]' не относится к текущей задаче. Операция отменена." и занести в `error_list.md`.

### 1. Резервное Копирование (только для редактирования)
- **Условие:** Если файл редактируется, а не удаляется или меняются только атрибуты.
- **Действие:** Создать `.bak` копию оригинального файла.
- **Команда:** `Copy-Item -Path [путь_к_файлу] -Destination [путь_к_файлу].bak`

### 2. Запись в Журнал Операций
- **Условие:** Всегда.
- **Действие:** Добавить запись о намечаемой операции в `file_operations.log`.
- **Формат записи:** `[YYYY-MM-DD HH:MM:SS] - НАМЕРЕНИЕ: [РЕДАКТИРОВАТЬ/УДАЛИТЬ/ИЗМЕНИТЬ АТРИБУТЫ] - ФАЙЛ: [полный_путь_к_файлу]`

### 3. Запрос Разрешения у Пользователя
- **Условие:** Всегда.
- **Действие:** Запросить явное разрешение пользователя с помощью `ask_user`.
- **Формат вопроса:** "Я собираюсь [ОТРЕДАКТИРОВАТЬ/УДАЛИТЬ/ИЗМЕНИТЬ АТРИБУТЫ] файл [имя_файла]. Вы разрешаете это действие?"

### 4. Исполнение
- **Условие:** Только если на шаге 3 получен ответ "Да".
- **Действие:** Выполнить запланированную операцию (`replace`, `write_file`, `Remove-Item`, `Set-ItemProperty`).
- **Отмена:** Если получен ответ "Нет", операция полностью отменяется. Сообщить пользователю: "Действие отменено по вашему указанию."
