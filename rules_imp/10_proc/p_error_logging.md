# Протокол Фиксации и Анализа Ошибок (p_error_logging.md)

**Принцип:** III. Error Logging & Analysis (Non-Negotiable)  
**Версия:** 1.0.0  
**Создан:** 2026-03-29

---

## Назначение

Этот протокол обеспечивает **обязательную фиксацию и анализ всех ошибок** через Root Cause Analysis (5 Why's).

---

## Классификация Ошибок

| Тип | Описание | Примеры |
|-----|----------|---------|
| **Системная** | Ошибки ОС, доступ к файлам | EPERM, EACCES, ENOENT |
| **Синтаксическая** | Ошибки в коде до запуска | SyntaxError, TS1005 |
| **Runtime** | Ошибки во время выполнения | TypeError, NullReference |
| **Логическая** | Код работает, но неверно | Неверный результат |
| **Контекстная** | Нехватка информации | "Информация не найдена" |

---

## Протокол Фиксации

### Шаг 1: Запись в error_list.md

**Формат записи:**

```markdown
## [YYYY-MM-DD HH:MM:SS] [Тип Ошибки]

**Файл/Операция:** [путь или описание]

**Текст ошибки:**
```
[полный текст ошибки]
```

**Контекст:**
- Что делал: [описание действия]
- Ожидалось: [ожидаемый результат]
- Фактически: [фактический результат]

**Причина (Root Cause Analysis - 5 Why's):**
1. Почему? → [причина 1]
2. Почему? → [причина 2]
3. Почему? → [причина 3]
4. Почему? → [причина 4]
5. Почему? → [корневая причина]

**Рекомендации:**
1. [рекомендация 1]
2. [рекомендация 2]

**Связанный урок:** [ссылка на lessons/]

**Результат:** [Успешно/Не успешно]
**Время исправления:** HH:MM:SS
```

### Шаг 2: Root Cause Analysis (5 Why's)

**Пример:**

```
Ошибка: EPERM при редактировании файла

1. Почему? → Файл заблокирован или read-only
2. Почему read-only? → Установлен атрибут R
3. Почему установлен? → Пользователь защитил файлы правил
4. Почему не проверил? → Нет проверки в протоколе
5. Почему нет? → Протокол не включал этот шаг

Корневая причина: Протокол не включает проверку атрибутов файла
```

### Шаг 3: Решение о создании урока

**Создать урок если:**
- Получено новое знание из диалога с пользователем
- Потребовался синтез данных из ≥3 файлов
- Первоначальная стратегия привела к ошибке

## Примеры Записей

### Пример 1: Системная ошибка (EPERM)

```markdown
## [2026-03-29 14:35:22] [Системная - EPERM]

**Файл/Операция:** `rules_imp/10_proc/p_loop.md` (редактирование)

**Текст ошибки:**
```
Error: EPERM: operation not permitted, open 'C:\CLI\Pi\rules_imp\10_proc\p_loop.md'
```

**Контекст:**
- Что делал: Пытался обновить файл правил через replace
- Ожидалось: Файл обновлён
- Фактически: Ошибка доступа

**Причина (5 Why's):**
1. Почему? → Файл заблокирован или read-only
2. Почему read-only? → Установлен атрибут R
3. Почему установлен? → Пользователь защитил файлы правил
4. Почему не проверил? → Нет проверки в протоколе
5. Почему нет? → Протокол не включал этот шаг

**Рекомендации:**
1. Проверять атрибуты перед редактированием
2. Снимать read-only через Set-ItemProperty
3. Восстанавливать атрибут после редактирования

**Связанный урок:** `lessons/Диагностика_ошибок_доступа_к_файлам.md`

**Результат:** Успешно
**Время исправления:** 00:05:32
```

### Пример 2: Синтаксическая ошибка

```markdown
## [2026-03-29 15:10:45] [Синтаксическая - TypeScript]

**Файл/Операция:** `src/utils.ts` (компиляция)

**Текст ошибки:**
```
error TS1005: ';' expected.
```

**Контекст:**
- Что делал: Компиляция TypeScript
- Ожидалось: 0 ошибок
- Фактически: 1 ошибка синтаксиса

**Причина (5 Why's):**
1. Почему? → Пропущена точка с запятой
2. Почему пропущена? → Автоформатирование не добавило
3. Почему не проверил? → Не запустил tsc --noEmit
4. Почему не запустил? → Забыл о проверке
5. Почему забыл? → Нет чек-листа проверки

**Рекомендации:**
1. Добавить точку с запятой
2. Запустить tsc --noEmit перед завершением
3. Добавить чек-лист проверки

**Результат:** Успешно
**Время исправления:** 00:02:15
```
