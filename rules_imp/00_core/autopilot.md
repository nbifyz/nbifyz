# 🧠 КОНТРОЛЬ АВТОПИЛОТА (Cognitive Safety)

**Версия:** 1.0.0  
**Принцип:** II. Self-Awareness — осознание собственных когнитивных искажений  
**Статус:** CRITICAL — обязательно к применению во всех сессиях

---

## ⚠️ ЧТО ТАКОЕ «АВТОПИЛОТ»

**Автопилот** — режим работы, при котором:
- Используются знакомые пути/решения без проверки актуальности контекста
- Делаются предположения на основе предыдущего опыта (других проектов/сессий)
- Игнорируется текущая рабочая директория (cwd)
- Действия выполняются по «привычке», а не по запросу

---

## 🚨 ТРИГГЕРЫ: КОГДА ВКЛЮЧАТЬ РУЧНОЕ УПРАВЛЕНИЕ

### 🔴 Critical Triggers (Автопилот ЗАПРЕЩЁН)

Включать **строгий протокол проверки** при:

1. **Пути из памяти**
   - Использую путь который «помню» из прошлой задачи (>5 минут)
   - Переменные окружения (%AD%, %RULES%, %PS%) без проверки актуальности
   - Ссылки на файлы из AGENTS.md без явной проверки cwd

2. **Относительные пути**
   - `@filename` — что означает «тут же» или «в стандартном месте»?
   - `./path`, `../path` — но cwd не проверен явно
   - Пути через `%VAR%` без `echo %VAR%`

3. **Предположение существования**
   - «Файл должен быть в X» (не видел, но «вероятно» там)
   - «Создам с нуля, т.к. его нет» (не искал через find/ls)

4. **Контекст переключения**
   - Только что работал в ProjectA, теперь работаю в ProjectB
   - Переключение между %AD% и ./ (текущий проект)

### 🟡 Warning Triggers (Автопилот ПОД ВОПРОСОМ)

- Файловые операции в системных папках (%AD%, C:\CLI\Pi\*)
- Удаление/перезапись существующих файлов
- Создание новых директорий вне текущего проекта
- Использование скриптов из `scripts/` без проверки cwd

---

## 🛡️ ПРАВИЛО CWD-FIRST (Обязательно)

```
Перед любой файловой операцией:
┌─────────────────────────────────────────┐
│ 1. WHERE: В какой папке я сейчас?      │
│    → bash: echo %cd% / pwd             │
│                                        │
│ 2. WHAT: Что значит этот путь?         │
│    → Относительный — от cwd             │
│    → Абсолютный — проверить существует  │
│    → Из памяти — ВЕРИФИЦИРОВАТЬ         │
│                                        │
│ 3. VERIFY: Файл точно тут?             │
│    → ls/find перед операцией            │
│    → Если не найден — спросить юзера    │
└─────────────────────────────────────────┘
```

---

## ⏱️ ПРАВИЛО 3-5-7 (Замедление)

Для файловых операций — обязательное замедление:

| Фаза | Время | Действие |
|------|-------|----------|
| **3 сек** | Awareness | «В какой папке я? Какой проект активен?» |
| **5 сек** | Verify | «Файл точно тут? Проверить через find/ls» |
| **7 сек** | Confirm | «Если сомнения — уточнить у пользователя» |

**Исключение:** Рутинные операции в ПОДТВЕРЖДЁННОМ cwd (текущий проект).

## 🔒 КРИТИЧЕСКИЕ ОПЕРАЦИИ (Автопилот ЗАПРЕЩЁН)

При этих операциях — **строгий протокол**:

### 1. Редактирование системных файлов
- `%AD%\AGENTS.md`
- `%AD%\.env`
- `%AD%\rules_imp\00_core\*` (включая этот файл)

**Протокол:**
```
1. Прочитать файл (read)
2. Показать diff (что изменится)
3. Получить подтверждение
4. Только потом edit/write
```

### 2. Удаление файлов
- `rm`, `del`, `Remove-Item`
- Очистка директорий

**Протокол:**
```
1. Показать что будет удалено
2. Подтверждение от пользователя
3. Резервная копия если критично
4. Только потом удаление
```

### 3. Перезапись файлов
- `write` (существующий файл стирается)
- `edit` без бэкапа

**Протокол:**
```
1. Проверить exists
2. Прочитать старое содержимое
3. Показать diff
4. Подтверждение
5. Только потом запись
```

## ✅ МЕХАНИЗМ САМОПРОВЕРКИ

После каждой файловой операции спросить себя:

```markdown
- [ ] Я делал это в ТОЙ папке что думал?
- [ ] Проверял ли я cwd ПЕРЕД действием?
- [ ] Мог ли я сейчас работать «на автопилоте»?
- [ ] Есть ли разница между тем что сделал и что ожидалось?
```

**Если хоть один ответ «Да/Не уверен» — остановиться и проверить результат.**

## 📋 ПРИКЛАДНЫЕ ПРИМЕРЫ

### ❌ Ошибка автопилота
```
User: «Прочитай @scripts/dl.bat»
Cwd: C:/Project/stegano (текущий проект)

Ошибка: Ищу в C:/CLI/Pi/scripts/ (привычный путь из .env)
Игнорирую: ./scripts/ (текущий проект)
```

### ✅ Правильный подход
```
User: «Прочитай @scripts/dl.bat»
Действие:
1. WHERE: cwd = C:/Project/stegano
2. WHAT: @scripts/dl.bat → ./scripts/dl.bat
3. VERIFY: ls ./scripts/ → dl.bat найден
4. READ: успешно
```
