# SEARCH MASTERY (Скилл Мастерства Поиска) — v2.0 STRICT

   ПЕРЕД каждой попыткой поиска ОБЯЗАТЕЛЬНО:
   1. Читать этот документ полностью
   2. Читать `use_rg.md` полностью
   3. Записывать в журнал поиска факт прочтения инструкций

   НЕТ ИСКЛЮЧЕНИЙ. ДАЖЕ ЕСЛИ КАЖЕТСЯ ВСЕ ПРОСТЫМ.
 ```
   - Результат кажется очевидным → Проверить ВСЕ возможные источники
   КАЖДОЕ РУКОВОДСТВО ДОЛЖНО БЫТЬ ПРОЧИТАНО, ДАЖЕ ЕСЛИ ОТВЕТ УЖЕ ИЗВЕСТЕН.
 ```

## 1. ПРИНЦИП "ЧИСТОГО ЛИСТА"

    ЗАПРЕТ НА ЛОГИ: Файлы .jsonl, папки sessions и persistent_history.log — это МУСОР. Игнорировать их при поиске фактов.
    ФАКТ = ФАЙЛ: Данные существуют, только если они есть в .md, .txt, .py, .json или .bat в папке проекта.
    ИНТУИЦИЯ OFF: Нет результата в файлах — значит данных НЕТ. 
	ЗАПРЕЩЕНО выдумывать или брать из памяти чата. 
	Ответ: "Информации в файлах проекта не найдено".

## 2. АЛГОРИТМ "ПИЩЕВОЙ ЦЕПОЧКИ"
- Используй скиллы из  `C:\CLI\pi\rules\skills\`.
Например для поиска в документах `\find_in_docs`
- если нет точного скила - используй наиболее подходящий.
- Если rg выдал пустоту:
    Снизь строгость: Например ищи корень слова (не "Монстры", а "Монстр").
    Кириллица: ВСЕГДА используй rg -i (игнор регистра).
    Локация: Проверь корень . и вложенные папки отдельно.
    Инструкция: ПЕРЕД поиском перечитай ./rules/use_rg.md.

## 3. ПРОТОКОЛ ОТЧЕТНОСТИ (Proof of Search)
При нахождении информации агент ОБЯЗАН выдать блок:

    Команда: Какую именно rg -nH команду использовал.
    Источник: Имя файла и НОМЕР СТРОКИ.
    Цитата: Прямая выдержка из найденной строки.
    Вердикт: "Данные взяты из исходника на диске".

## 3.1. ТРИГГЕР-ЗАМОК (ОБЯЗАТЕЛЬНО)

    НЕТ ПРУФА = НЕТ ФАКТА: Ответ без rg -nH и номера строки — это галлюцинация.
    ДВОЙНОЙ ВВОД:
        Сообщение 1: Вызов инструмента rg.
        Ожидание ответа от ПИ (исполнителя).
        Сообщение 2: Анализ результата и цитирование.
    ЗАПРЕТ: Запрещено ссылаться на "память", "прошлые сессии" или "общие знания".

## 4. СТОП-СИГНАЛЫ (Анти-Галлюцинация)

    - Просили найти данные, а ты начал писать код? СТОП.
    - Нашел ответ в sessions/*.jsonl? СТОП. Удали и ищи в исходниках.
    - Не можешь дать номер строки в текущем Workdir? ОТВЕТА НЕТ.
	- Если во время поиска:  чувствуеш "это просто" → ОСТАНОВИТЬСЯ и перечитать инструкции             
	- Если хочеш пропустить шаг → ОБЯЗАТЕЛЬНО выполнить его двойной проверкой                          
	- Результат кажется очевидным → Проверить
	
## 5. Разрешается давать ответ толко в том случае если данные запроса находились в разных  файлах. 
в этом случае необходимо подтвердтить свой  ответ цитатами из найденого.
Пользователь может временно  отключить опцию `подтверждения цитированием` в произвольной форме.
