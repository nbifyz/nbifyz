# Навык: Code Accuracy (s_code_accuracy.md)

**Принцип:** II. Code Accuracy (Non-Negotiable)  
**Версия:** 1.0.0  
**Создан:** 2026-03-29

---

## Назначение

Этот навык обеспечивает **максимально достоверное написание кода** через синтаксическую проверку и следование паттернам проекта.

---

## Протокол Применения

### Шаг 1: Перед написанием кода

**ОБЯЗАТЕЛЬНО:**
1. Изучить существующие паттерны в проекте
2. Определить язык и фреймворк
3. Проверить зависимости (package.json, requirements.txt, Cargo.toml)

### Шаг 2: Синтаксическая проверка

**Для каждого языка — своя команда:**

| Язык | Команда проверки |
|------|------------------|
| **TypeScript/JavaScript** | `tsc --noEmit` или `npm run lint` |
| **Python** | `python -m py_compile файл.py` |
| **PowerShell** | `Invoke-ScriptAnalyzer -Path файл.ps1` |
| **Rust** | `cargo check` |
| **Go** | `go build ./...` |
| **Batch** | `cmd /c файл.bat` (проверка синтаксиса) |

### Шаг 3: Dry Run (Сухой прогон)

**Перед завершением задачи:**
1. Проверить логику без выполнения
2. Убедиться в отсутствии побочных эффектов
3. Проверить обработку ошибок

---

## Команды Проверки

### TypeScript/JavaScript

```bash
# Синтаксическая проверка
tsc --noEmit файл.ts

# ESLint (если настроен)
npm run lint

# Проверка конкретного файла
eslint файл.js
```

### Python

```bash
# Синтаксическая проверка
python -m py_compile файл.py

# Flake8 (стиль и ошибки)
flake8 файл.py

# Pylint (полная проверка)
pylint файл.py
```

### PowerShell

```powershell
# Анализ скрипта
Invoke-ScriptAnalyzer -Path файл.ps1 -Severity Error

# Проверка синтаксиса
powershell -NoProfile -Command "Get-Content файл.ps1 | Invoke-Expression"
```

### Batch

```batch
:: Проверка синтаксиса
cmd /c файл.bat /?

:: Запуск с проверкой ошибок
call файл.bat && echo Успех || echo Ошибка
```

## Протокол Следования Паттернам

### Анализ существующего кода

**Перед написанием нового кода:**

```bash
# Найти существующие функции
rg "function\s+\w+" src/

# Найти импорты
rg "^import\s+" src/

# Найти классы
rg "^class\s+\w+" src/
```

### Применение паттернов

**Обязательно:**
1. Использовать тот же стиль именования
2. Следовать той же структуре файлов
3. Применять те же соглашения о форматировании

---

## Примеры Использования

### Пример 1: Проверка TypeScript

**Задача:** Написать функцию для поиска файлов

**Код:**
```typescript
function findFiles(pattern: string, path: string): string[] {
    // Реализация
}
```

**Проверка:**
```bash
tsc --noEmit src/findFiles.ts
```

**Отчёт:**
```markdown
**Code Accuracy Check:**
- Язык: TypeScript
- Команда: `tsc --noEmit src/findFiles.ts`
- Результат: ✅ 0 ошибок
- Dry Run: ✅ Логика проверена
```

### Пример 2: Проверка Python

**Задача:** Написать скрипт для обработки данных

**Код:**
```python
def process_data(data: list) -> dict:
    # Реализация
    pass
```

**Проверка:**
```bash
python -m py_compile src/process_data.py
flake8 src/process_data.py
```

**Отчёт:**
```markdown
**Code Accuracy Check:**
- Язык: Python
- Команда: `python -m py_compile src/process_data.py`
- Результат: ✅ 0 синтаксических ошибок
- Flake8: ✅ 0 предупреждений
- Dry Run: ✅ Логика проверена
```

### Пример 3: Частичное выполнение (честный отчёт)

**Задача:** Проверить 10 файлов проекта

**Отчёт:**
```markdown
**Честный отчёт о частичном выполнении:**

**Проверено:** 7 из 10 файлов (70%)

**Проверенные файлы:**
1. src/main.ts — ✅ 0 ошибок
2. src/utils.ts — ✅ 0 ошибок
3. src/config.ts — ✅ 0 ошибок

**НЕ проверенные файлы:**
1. src/test.ts — отсутствует tsc
2. src/lib/helper.ts — файл заблокирован
3. src/plugins/index.ts — путь не найден

**Предложение:** Повторить проверку через 5 минут после установки TypeScript.
```

## Запреты

**ЗАПРЕЩЕНО:**

1. ❌ Писать код без синтаксической проверки
2. ❌ Игнорировать ошибки компиляции
3. ❌ Использовать паттерны, не соответствующие проекту
4. ❌ Пропускать dry run для сложной логики
5. ❌ Скрывать ошибки компиляции от пользователя

**Разрешено:**

1. ✅ Сообщать о синтаксических ошибках
2. ✅ Предлагать исправления
3. ✅ Честно докладывать о частичной проверке
