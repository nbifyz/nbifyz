# Навык: Тестирование (TDD)
*Версия 4, STRICT*

Этот документ объединяет высокоуровневые принципы TDD и конкретные дисциплинарные практики.

---

## 1. Ключевые Принципы TDD

- **Принцип:** **Fail → Code → Pass → Refactor**. Сначала пишется тест, который падает, затем код, который заставляет его пройти, после чего код рефакторится.
- **Покрытие:** Код должен иметь покрытие тестами > 80%.
- **Типы тестов:** Обязательны модульные (unit) и интеграционные (integration) тесты.
- **Инструменты:** ОБЯЗАТЕЛЬНО использовать `dry_run_analyzer.py` и `hallucination_detector.py` перед тестированием.
- **Финал:** Запуск `test_finale.bat` перед сдачей любой задачи.
- **ЗАПРЕТ:** Любой код без предварительного сухого прогона (`dry_run`) считается невалидным и не подлежит тестированию.

---

## 2. Дисциплина и Уровни Тестирования

### Правило
**ВСЕГДА** проверять код на исполнение после **каждого** изменения.

### Уровни

#### 1. Модульное (Unit Testing)
Тест изолированной функции или компонента.
```python
# Тест отдельной функции
def test_add():
    assert add(2, 3) == 5
```

#### 2. Интеграционное (Integration Testing)
Тест взаимодействия нескольких модулей.
```python
# Тест взаимодействия модулей
def test_file_processing():
    result = process_file("test.txt")
    assert result is not None
```

#### 3. Системное (System Testing)
Запуск всего сценария или приложения для проверки сквозной функциональности.
```bash
# Запуск всего скрипта
python main.py --input test.txt
```

---

## 3. Практики Проверки

### Что проверять
- ✅ **Возвращаемые значения:** Соответствует ли результат ожидаемому.
- ✅ **Побочные эффекты:** Не изменяется ли состояние системы непредсказуемым образом.
- ✅ **Граничные случаи:** (0, -1, пустые строки, большие значения).
- ✅ **Обработку ошибок:** Корректно ли выбрасываются и обрабатываются исключения.

### Когда тестировать
- ✅ После **каждого** атомарного изменения.
- ✅ Перед коммитом или отправкой кода.
- ✅ При получении новых или изменении существующих требований.
